# Multi-idioma (i18n)

Referencia: [ADR-0005](adr/0005-idiomas-e-i18n.md). Idiomas del MVP: **`es` (por defecto)** y
**`en`**. La lista de idiomas vive en `src/domain/catalog/locale.ts` (`SUPPORTED_LOCALES`) y todo
lo demás se deriva de ahí: URLs, diccionarios, `lang`, `hreflang` y el selector de idioma.

## Dos capas de traducción

| Capa                                     | Dónde vive                             | Quién la escribe               |
| ---------------------------------------- | -------------------------------------- | ------------------------------ |
| Textos de interfaz (botones, avisos)     | `messages/<locale>.json` (repositorio) | El equipo, en el PR            |
| Textos de catálogo (nombre, descripción) | Base de datos, tabla `catalog_text`    | El propietario, desde el panel |

Los textos de catálogo tienen **fallback a español**: si falta una traducción se sirve la de `es`
y el panel marca lo que falta con `LocalizedText.missingLocales()`
(`src/domain/catalog/catalog-text.ts`).

## URLs y detección de idioma

- Todas las rutas llevan prefijo (`/es/...`, `/en/...`) y la raíz redirige al idioma por defecto
  (`/` → `/es`). Lo hace `src/proxy.ts` (Next.js 16: el antiguo `middleware` ahora se llama
  `proxy`).
- El `<html lang>` se emite desde `src/app/[locale]/layout.tsx`.
- La canónica y los enlaces `rel="alternate" hreflang` (más `x-default`) **dependen de la ruta**.
  El layout solo aporta el título y la descripción por defecto; cada página declara los suyos con
  `buildLocaleAlternates(pathname, locale)` (`src/i18n/alternates.ts`), que apunta a la ruta
  hermana en cada idioma. Una página nueva que olvide ese metadata no hereda una canónica
  equivocada: simplemente no emite ninguna.
- Orden de detección de next-intl: prefijo de la URL → cookie `NEXT_LOCALE` → `Accept-Language` →
  idioma por defecto.

## Presupuesto: PDF y email en el idioma del configurador

El presupuesto **recuerda su idioma**: se guarda `locale` al emitirlo (`ManualQuoteRequest.locale`,
ADR-0005). El PDF y el email se renderizan siempre con el idioma guardado, no con el de la petición
actual:

```ts
const t = await getTranslations({ locale: quote.locale, namespace: 'Quote' })
```

- Namespace `Quote` en `messages/<locale>.json`: `documentTitle`, `reference`, `issuedOn`,
  `validUntil`, `customer`, `configuration`, `series`, `measurements` (`measurementFormat`),
  `finish`, `color`, `accessories`, `unitPrice`, `subtotal`, `taxRate`, `total`,
  `frozenPriceNotice`, `manualQuoteNotice`, `contactPrompt`, `email.*` y `pdf.*`.
- Zona horaria y formato fijados en `src/i18n/request.ts` (`Europe/Madrid`) para que fechas e
  importes no dependan del servidor.
- Historia completa del flujo en [ADR-0004](adr/0004-presupuesto-pdf-y-email.md).

## Panel

- Namespace `CatalogAdmin`: estados vacío/carga/error, acciones y el aviso de traducción pendiente.
- Etiquetas de idioma para cualquier selector: `LanguageSwitcher.options.<locale>`.
- Estado de traducción por campo: `availableLocales()` / `missingLocales()` del agregado
  `LocalizedText`; el aviso se compone con `CatalogAdmin.missingTranslation` y `{language}`.

## Errores de dominio

Los códigos estables del dominio se traducen con `DomainErrors.<CODE>` (`src/i18n/domain-errors.ts`).
Ese módulo incluye una comprobación **en tiempo de compilación** (`ALL_DOMAIN_ERRORS_TRANSLATED`):
si el dominio añade un `DomainErrorCode` sin mensaje, no compila.

## Cómo añadir un idioma

1. Añadir el idioma a `SUPPORTED_LOCALES` en `src/domain/catalog/locale.ts`.
2. Crear `messages/<locale>.json` con **todas** las claves (el test de paridad falla si falta una).
3. Traducir el catálogo desde el panel; mientras falte, se sirve español.

No se toca código de componentes ni de rutas.

## Qué impide dejar textos sin traducir

- `src/i18n/messages.test.ts`: un diccionario por idioma soportado, mismas claves en todos,
  ningún texto vacío, mismos marcadores ICU y todos los errores de dominio traducidos.
- `e2e/i18n.spec.ts`: cambio de idioma con URLs por idioma, `lang`, `canonical`, `hreflang`,
  `x-default`, persistencia real en la cookie `NEXT_LOCALE` (el idioma elegido decide luego la
  raíz) y caída al español por defecto cuando `Accept-Language` no incluye español, en escritorio
  y móvil.
- Definition of Done: sin literales de interfaz hardcodeados (ADR-0005).

## Uso en componentes

```tsx
// Componente de servidor
const t = await getTranslations('Home')

// Componente de cliente (dentro de NextIntlClientProvider, ya montado en el layout)
const t = useTranslations('Home')

// Navegación que conserva el idioma
import { Link, usePathname } from '@/i18n/navigation'

// Selector de idioma accesible ya incluido
import { LocaleSwitcher } from '@/ui/locale-switcher'
```

## Canónica y `hreflang` de una ruta nueva

```tsx
// src/app/[locale]/configurador/page.tsx
import { buildLocaleAlternates } from '@/i18n/alternates'

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { locale } = await params

  return { alternates: buildLocaleAlternates('/configurador', locale) }
}
```

`buildLocaleAlternates` ignora la query y el fragmento (una canónica nunca los incluye),
normaliza barras sobrantes y devuelve `canonical` más un `hreflang` por idioma soportado con
`x-default` apuntando al idioma por defecto.
